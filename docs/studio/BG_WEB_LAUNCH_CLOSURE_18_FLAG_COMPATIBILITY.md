# BG-WEB-LAUNCH-CLOSURE-18 — WEB feature flags versus API capability (fail-closed compatibility gate)

13 Nov 2026. Authority: accepted API main **`5cd1d774e04fcbfb0745d9bd5c7a0b974cd982f5`**; WEB base `df3b95d9ed462264669fc9640f3259739a33f2df`. Supersedes the route classifications of the Closure-16 matrix (written against `d3ec6c37`); read together with `BG_WEB_LAUNCH_CLOSURE_17_API_SOURCE_CORRECTION.md`. Source verification only: no staging revision, hosted environment, provider or credential was inspected. Staging and launch remain NO-GO.

## 1. The problem this closes
The API has **no capability or revision endpoint** (`GET /` returns a fixed status string), and several routers are mounted with a `null` service that answers a controlled 503 unless the operator enables and configures the service. A WEB build flag therefore says nothing about whether the serving API can do the thing. The staging workflow turns on four flags (quote, workspace calendar, customer media, social); against a revision that lacks the routes or configuration the customer would see controls that cannot work, and, before this change, a missing route read as “not available to you”.

## 2. The gate (source, `src/premium/featureGate.js`, `apiCompatibility.js`)
A gated control is shown only if **all** hold: the flag is `true`; the build **declares** the API it targets (`VITE_API_SOURCE_SHA`, 40-hex source commit, and `VITE_API_SERVING_REVISION`); and `apiCompatibility.js` lists that exact pair with an evidence URL and marks the feature's capability `true`. Anything else is OFF: no revision declared, malformed declaration, revision or SHA not in the manifest (a WEB/API revision mismatch), capability not verified, malformed manifest entry (ignored whole). Social providers are narrowed to the verified entry's `socialProviders`. Browser test doubles (`.test`/`.example`/`.invalid`/`.localhost` or loopback API URL) are exempt, because they cannot be a deployed revision; unit tests are lenient unless they request `VITE_API_COMPAT_MODE=enforce`, and that variable is ignored in every release build. **The shipped manifest is empty, so every gated control is OFF in every release build until a reviewed PR adds evidence.** The staging workflow was not edited; a test derives the exposure from the workflow file itself.
Failure wording (`routeAbsent.js`): a 404 **without** an API error code (the framework’s answer for an unmounted route) now says the feature “isn't available in this version yet… your access has not changed” (`code ROUTE_NOT_DEPLOYED`). A 404 that carries an API code (a real authorisation refusal) keeps its access wording; 503 keeps its “not switched on / temporarily unavailable” wording. Applied to quotes, creative jobs, media intake, social, insights, workspace calendar, plan catalogue, credit preview, billing management and invoices.

## 4. Result and how a feature is released
**WEB/API staging compatibility: BLOCKED, by design.** Every flagged control is OFF in the next staging build because no API revision is declared and none is verified. Per feature, release needs: (1) a staging revision built from an accepted API commit with the activation flags and configuration above evidenced from the real revision (metadata collector or operator); (2) a hosted check that the route answers 2xx for the test tenant; (3) a reviewed WEB PR adding the manifest entry (sha, revision name, date, evidence URL, verified capabilities, social providers) **and** the workflow/Pages setting of `VITE_API_SOURCE_SHA` and `VITE_API_SERVING_REVISION` under the founder's deployment approval. This PR does not deploy, edit the workflow or change any setting.
## 5. Bounded Codex request (only what is genuinely absent on `5cd1d774`)
A read-only, non-sensitive **capability report** the WEB can use instead of a hand-maintained manifest: for example `GET /customer/capabilities` (authenticated) returning `{ api_source_sha, serving_revision, capabilities: { quotedGeneration, mediaIntake, social: [providers], learning, commercialCatalogue, creditPreview } }` from `createPremiumComposition().capabilities` plus catalogue/policy presence, with no secret, no configuration value and no tenant data. Optional; the manifest gate stands on its own. Nothing else is requested; no mounted route is asked for again.
